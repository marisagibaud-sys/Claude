Part 1 — Get it online

you, this week

1 · Open it and make it yours

≈ 5 minutes
  1. Open the Position Archive. It is already live — private to you until you share it in Stage 6.
  2. Click Guide (top right) and save your initials — records you file will carry them.
  3. File one test email: drag a saved .msg or .eml onto the page (or use + Add record). Confirm the components — Grade, Salary Range, FLSA, Reports to, and the rest — were read out of the body automatically. Fix anything with Edit, or delete the test.
Why first: thirty seconds of dragging one real email tells you the parser handles your format before you invest in the flow or the backfill.

2 · Seed a starter set

≈ 30 minutes
  1. In Outlook, pick 15–25 representative emails — a few New Position and a few Job Description from each of the last few years.
  2. Select them, drag them into a desktop folder (Outlook saves them as .msg), then drop the whole folder's contents anywhere on the archive page in one go.
  3. Skim the results: correct any kind the guesser got wrong, and set Department on each (departments power a filter, so consistent names pay off — decide now whether it's "Research" or "Research Dept").
Why before sharing: the team's first impression will be a search that finds things — not an empty page. Real records also make the coverage chart show where backfill is still needed.

3 · Wire the ongoing Outlook feed

≈ 1 hour, one-time · needs the GitHub token

Same trust model as the board: Claude never touches the mailbox. A Power Automate flow you control pushes categorized emails into the repo, and a scheduled sweep (weekdays, three times a day) files them into the archive.

  1. Reuse the fine-grained GitHub token from the board flow (repo-scoped, Contents: Read and write) — or mint a fresh one the same way.
  2. Clone the board's flow and make the four changes for the archive, or build from the full recipe in archive-inbox/README.md:
    • Filter on the two archive categories:
      categories/any(c:c eq 'New Position') or categories/any(c:c eq 'Job Description Review/Update') — and exclude an 'Archived' marker category instead of 'Logged'.
    • Select the body — add body to the $select list, and add "body" / "bodyType" to the Compose payload. This is what preserves the actual job description text.
    • Destination folder — archive-inbox/, not inbox/.
    • Branch — claude/email-archive-positions-v00ubh.
  3. Test end-to-end: categorize one email in Outlook, run the flow manually, and confirm a new .json appears in archive-inbox/ on GitHub. After the next weekday sweep, the record appears in the archive and the Guide drawer shows "Automation active".

4 · Backfill the legacy history

spread over days or weeks — it doesn't block Part 2

Two methods, safe to mix — duplicates are skipped automatically (by message id, and by identical subject + date), so overlapping runs are harmless.

  • Drag & drop by era — search a year or a folder in Outlook, select all, drag to desktop, drop the batch on the page. Best when the history lives in your own mailbox and you want to review as you go.
  • One-time flow runs — point the Stage 3 flow's query at the past, one year at a time (the exact dated $filter is in the recipe README). Best for volume.

Steer by the coverage chart: each bar is a year, and a missing bar is a gap still waiting on backfill. You don't need completeness before inviting the team — gaps are visible, so backfill can be shared work (Stage 8).

Part 2 — Bring the team in

week two

5 · Decide roles before you share

≈ 10 minutes of thinking
  • Everyone searches. That's the point — no training needed beyond "there's a search box".
  • Start with a small editor group — you plus one or two teammates who own filing and backfill. Widen once the conventions (Stage 7) have settled. People without edit access see a "View only" chip; nothing they try to change is saved.
  • Name a backup owner for the automation — someone besides you who knows where the flow, the token, and the recipe README live.

6 · Share the page

≈ 2 minutes
  1. On the archive page, open the share menu and grant access to your teammates — the artifact stays private until you do this.
  2. Have one teammate open the link, run a search, and (if they're an editor) file one record — confirm their save lands and everyone sees it.
  3. Tell editors to save their initials via the Guide drawer on first visit.

7 · Announce it

copy, tweak, send

New: the Position Archive

We now have one shared, searchable home for the emails that created and described our positions — every New Position announcement and Job Description we can recover, with the full text preserved: [paste the archive link here]

Finding things: type anything in the search box — a title, a grade ("GR 17"), a name, a phrase from a JD. Filter by kind, department, or year. Click a record to read the full original email; details like Grade, Salary Range, FLSA, and Reports To are pulled out as fields on each record.

Adding things: if you come across an old position or JD email that isn't in the archive yet, drag the email out of Outlook to your desktop and drop the file onto the page — it takes about ten seconds and the details fill themselves in. Rule of thumb: if you had to dig it out of your mailbox, file it so the next person doesn't have to.

Mail categorized New Position or Job Description Review/Update in Outlook is archived automatically going forward — the archive is for the history that predates that.

Questions or a record that looks wrong? Tell [name] — everything is editable.

Send it wherever the team actually reads — and consider a 10-minute walkthrough at your next team meeting: one live search lands the idea faster than any writeup.

8 · Make it stick

the first two weeks decide whether it becomes a habit
  • "Touch it, file it." The one rule worth repeating: anyone who digs a position email out of their mailbox files it before closing it.
  • Divide the backfill. Assign owners by department or by era ("Sam takes 2019–2021"). The coverage chart is the progress tracker — gaps close visibly, which keeps it moving.
  • A weekly 10-minute skim for the first few weeks: check new records for kind and department consistency (merge naming variants with Edit), and glance at the Guide drawer to confirm the automation is sweeping.
  • Use notes for lineage — when a JD supersedes an older one, add a note like "superseded by the 2024 re-level" so searchers land on the right version.

9 · Set the safety net

≈ 5 minutes, then monthly
  • Once real volume is in, click Export → JSON backup and keep the file somewhere durable. Repeat monthly — it's the complete archive including every body.
  • That JSON is also the migration file: when the new system is ready to hold this history, the archive hands it over in one structured export instead of another mailbox excavation.
  • The CSV export is for analysis — one row per record with all the component fields, ready for Excel.

If something looks off

"View only" chip
That person wasn't given edit access when the page was shared — re-share with edit rights, or they're a searcher by design.
"Not connected — changes stay on this screen only"
The page was opened outside claude.ai (e.g. a saved copy). Open it from the shared artifact link instead.
Flow's GitHub step returns 404
Almost always the branch or token: the PUT must target branch claude/email-archive-positions-v00ubh, and the token needs Contents: Read and write on this repo.
Pushed files but no records yet
The sweep runs on weekdays three times a day. Files wait in archive-inbox/ until then; the Guide drawer shows the last sweep time once it has run.
Components didn't extract
The extractor reads Label: value lines (Title, Grade, Salary Range, …) from the body. If an email formats them differently, open the record, click Edit, and fill the fields — they're ordinary text fields.
Same email showed up twice
Shouldn't happen via drag-drop or the flow (id and subject+date de-dup). If two genuinely different emails describe the same role, keep both — that's lineage, not duplication.
